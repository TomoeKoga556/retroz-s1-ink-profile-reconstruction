# Architecture

The public package separates rendering, measurement and evidence so a candidate
cannot declare itself successful.

```text
user-owned or synthetic RGB
            │
            ▼
public mask approximation / user labels
            │
            ▼
      candidate renderer
            │
            ├── output image
            ├── diagnostics
            └── provenance sidecar

independent repository checks
            ├── tests
            ├── document validation
            ├── asset/privacy scan
            └── SHA-256 manifests
```

## Package layers

`retroz_s1.cli` handles explicit user intent and refuses rejected candidate paths
without the acknowledgement flag. `retroz_s1.io` owns image conversion,
validation and provenance serialization. `retroz_s1.public_masks` provides a
clearly labelled approximation for public demonstrations. Candidate modules
contain the frozen historical implementations or renderers.

The candidate registry is shipped both at repository level and as package data.
Tests require both copies to match.

## Fail-closed behavior

Unknown candidates, malformed Oracle labels, unsupported render paths and missing
acknowledgements stop execution. Candidate A and C cannot be used as arbitrary
image filters; their public interface is a synthetic failure reproducer.

## Generated evidence

Synthetic visuals, report files, documentation and manifests are regenerated by
scripts in `scripts/`. CI builds the installed package rather than relying on a
repository-only `PYTHONPATH`, then checks that regeneration leaves the committed
tree unchanged.
